### Задача 3.
```bash
#!/usr/bin/env bash
echo "Используется гибкий shebang"
```
Объяснение сравнения:
* `./script.sh` запускает интерпретатор, указанный в shebang (`/usr/bin/env bash`). Требуются права на исполнение.
* `bash script.sh` принудительно исполняет код через Bash, игнорируя shebang. Права на исполнение не нужны.
* `sh script.sh` выполняет скрипт в режиме совместимости со стандартной командной оболочкой (sh). Если в коде используются специфичные для Bash конструкции (башизмы), скрипт выдаст ошибку синтаксиса.

### Задача 12.
```bash
MYVAR="secret"
bash -c 'echo "Без export: $MYVAR"'

export MYVAR
bash -c 'echo "С export: $MYVAR"'
```
Объяснение: Без вызова `export` переменная `MYVAR` является локальной для текущей оболочки и недоступна в дочерних процессах. Команда `export` делает её переменной окружения, передавая в среду окружения нового запущенного процесса `bash -c`.

### Задача 17. 
```bash
ls /nonexistent > /dev/null 2>&1
err_code=$?
echo "Код возврата для несуществующей директории: $err_code"

ls / > /dev/null 2>&1
success_code=$?
echo "Код возврата для успешного выполнения: $success_code"
```
Объяснение: Успешное выполнение команды всегда возвращает код `0`. Ошибки (например, отсутствие файла или папки) возвращают ненулевое значение (в случае с `ls` для несуществующего пути код равен `2`).
